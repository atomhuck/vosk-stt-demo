# Проверка и ограничения

## Автоматические проверки

```powershell
mvn -B clean test package javadoc:javadoc
mvn -B -f stt-service/pom.xml clean test package javadoc:javadoc
node --test stt-service/src/test/js/*.test.cjs
npx --yes @redocly/cli@2.71.1 lint docs/api/stt.openapi.yaml
npx --yes @redocly/cli@2.71.1 lint docs/api/analytics.openapi.yaml
```

Analytics-тест поднимает Spring Boot без Vosk-модели и проверяет авторизацию, порядок входящих и исходящих событий, идентификаторы сессии и закрытие канала при разрыве `sequence`. Тесты STT проверяют аудиокадры, захват и peer WebSocket. Тестовые записи и пользовательское аудио не хранятся в Git; проверки на реальной модели выполняются локально на внешних WAV-файлах.

GitHub Actions выполняет Maven-тесты и сборку двух сервисов, генерацию Javadoc, клиентские Node-тесты STT и линтинг обоих OpenAPI-контрактов. Реальные модели в CI не скачиваются.

## Проверка на реальных моделях

Перед выпуском выполните локальный сценарий до XLSX: запишите голосовой эталон, проверьте речь кандидата и интервьюера по очереди и при перекрытии, пропуск вопроса, отмену решения продолжением речи, уточнение Whisper и завершение отчёта. Сверьте `timeline.json`, `timeline-events.jsonl`, `stt-events.jsonl`, `integration-summary.json` и XLSX.

Автоматические тесты не подтверждают точность распознавания/диаризации в разных помещениях, качество микрофонов и задержки на другом оборудовании. Эти показатели зависят от реальных моделей, аудиоустройств и вычислительной нагрузки; численные гарантии не заявляются.
