# Внутренний WebSocket STT → analytics

Канал предназначен только для STT service. Analytics принимает JSON-события и не принимает аудиокадры. В локальном запуске адрес — `ws://127.0.0.1:8080/ws/interview-events`; handshake требует `X-Internal-Token`. В распределённом развёртывании используйте `wss` и внутреннюю сеть.

## Порядок соединения

Первое сообщение `start` задаёт идентификатор и выбранные уровни. Оно не содержит `sequence`. Все последующие сообщения содержат тот же `sessionId` и целое `sequence`, начиная с 1 и увеличивая на 1 для каждого события. Повторное событие с уже обработанным номером игнорируется; пропуск номера закрывает соединение с кодом 1008. Несовпадение сессии и неизвестный тип также приводят к `error` и закрытию.

```json
{
  "type": "start",
  "sessionId": "d3c0068c-...",
  "levels": []
}
```

## Сообщения STT → analytics

После `start` поддерживаются следующие типы. Все аудиопозиции — абсолютные номера PCM-сэмплов от начала сессии при частоте 16 кГц; временная отметка в секундах равна `sample / 16000`. WebSocket несёт только метаданные, PCM остаётся в STT service.

| Тип | Поля | Назначение |
|---|---|---|
| `ready` | `sessionId`, `sequence`, `audioStartSample` | Открыть окно ответа с абсолютной позицией начала. |
| `frame` | `audioStartSample`, `audioEndSample`, `samples`, `rms`, `asrMs`, `asrType`, `text` | Кандидат-гейтированный кадр. Границы задают интервал в общей шкале; `samples` — длину PCM-кадра, `rms` — RMS, `asrType` — пусто, `partial` или `final`, `text` — новая гипотеза Vosk. Кадр не содержит PCM. |
| `peek` | `requestId`, `text`, `audioStartSample`, `audioEndSample` | Рассчитать предварительную read-only подсказку по тексту кандидата и указать охваченный участок ответа. |
| `tts_end` | `afterMs`, `audioEndSample` | Отметить конец озвучивания вопроса и исключить его длительность из времени ответа. |
| `skip` | `audioStartSample`, `audioEndSample` | Пропустить вопрос; границы указывают текущую обработанную позицию аудиопотока. |
| `refined` | `answerId`, `text`, `audioStartSample`, `audioEndSample` | Передать уточнённый STT/Whisper текст принятого ответа с его аудиоинтервалом. |
| `refine_done` | `answerId`, `audioStartSample`, `audioEndSample`, `error?` | Завершить ожидание уточнения, в том числе при выключенном Whisper или ошибке. |
| `stop` | — | Завершить интервью и запросить отчёт. |

Кадры генерируются внутренним worker STT с шагом 50 мс. `samples` и `rms` передаются и для кадров тишины, чтобы аналитика могла измерить паузу и определить конец ответа. На финальном flush допустим кадр с `samples: 0` и последним текстом.

```json
{
  "type": "frame",
  "sessionId": "d3c0068c-...",
  "sequence": 18,
  "audioStartSample": 12800,
  "audioEndSample": 13600,
  "samples": 800,
  "rms": 532.4,
  "asrMs": 4.8,
  "asrType": "partial",
  "text": "виртуальная машина"
}
```

STT сначала отправляет `refined`, затем `refine_done` с тем же `answerId` и аудиоинтервалом. Analytics обновляет текст и оценку существующей попытки; событие не переигрывает решение или переход между вопросами.

## Сообщения analytics → STT

Все исходящие сообщения analytics содержат `sessionId`, собственный возрастающий `sequence` и `audioSample` — последний принятый абсолютный номер PCM-сэмпла. Это водяной знак состояния потока, а не границы аудио конкретного события.

| Тип | Основные поля | Назначение |
|---|---|---|
| `question` | `number`, `total`, `level`, `topic`, `text`, `spoken`, `followUp`, `graceMs` | Новый вопрос или уточнение. Следующий вопрос нельзя показывать до конца `graceMs`. |
| `partial` | `text` | Текущая распознанная гипотеза ответа. |
| `preview` | `requestId`, `action`, `reason`, `coveragePercent`, `recognized`, `readOnly` | Предварительный результат; не фиксирует состояние вопроса. |
| `decision` | `answerId`, `action`, `reason`, `coveragePercent`, `recognized`, `timing` | Принятое решение по ответу. |
| `retract` | `reason`, `question?` | Продолжение речи в grace-окне отменило решение; восстановлен прежний вопрос. |
| `refined` | `text` | Аналитика приняла уточнённый STT текст. |
| `finalizing` | `message` | Ожидание завершения уточнения текста перед отчётом. |
| `report` | `report`, `excel?` | Итоговая оценка и ссылка на XLSX. |
| `warning` / `error` | `code?`, `message` | Предупреждение о задержке STT или ошибка протокола/сессии. |

## Ошибки и границы данных

- Handshake без общего секрета длиной минимум 32 символа или с неверным значением получает HTTP 401.
- Ошибка идентификатора/порядка событий отправляет JSON `error` и закрывает соединение с кодом 1008. Если `start` уже принят, ошибка также содержит серверные `sessionId`, `sequence` и `audioSample`.
- STT передаёт только текст, временные/порядковые данные, RMS и метрики обработки. Сырые PCM-кадры остаются в STT service; внутренний Whisper helper получает только подтверждённые кадры кандидата.
- Если уточнение не пришло в пределах `interview.refinement-wait-ms`, analytics формирует отчёт на доступном тексте.
